# 排错表

按现象查。前三条占了「灯不亮」问题的九成。

---

## 灯完全不亮

| 检查 | 说明 |
|---|---|
| **1. 官方驱动退干净了吗** | AULA Hub（**含托盘图标**）会持续回写灯效，把你的颜色立刻覆盖掉。必须完全退出。SKYdimo 同理 |
| **2. `brightness` 是不是填了 255** | 量程是 **0–5**，填 255 会溢出 → **全黑**。这是本项目踩得最狠的一个坑 |
| **3. `mode` 是不是 20** | 其他值是板载内置动画，看起来「有灯」但**不是你写的自定义表** |
| **4. 打开的是 MI_03 吗** | 有线 `0xFF68:0x61`、无线 `0xFF60:0x61`。往 MI_04（`0xFF70`）写会「写入成功却全黑」 |
| **5. 128 槽都填了吗** | 只写 87 个槽，后 41 槽残缺 → 见下一条 |
| **6. 拔插 USB** | 键盘固件卡住时，**拔插必恢复** |

---

## 部分键不亮（功能区 / 右 Ctrl / 右 Shift / Enter）

**原因**：128 槽表里前 87 个之外没填，或槽 ID 字节被破坏。

固件按**数组下标**取色，所以第 `s` 槽的第一个字节必须写 `s`：

```js
for (let s = 0; s < 128; s++) table[s * 4] = s;   // ← 这行不能省
```

只把 87 个键的颜色写进去、让后 41 槽留空（Lua 里是 `nil`），
会破坏已校准槽位的 ID 字节，表现为**功能区、右 Ctrl/Shift、Enter 不亮**。

> 同理：SKYdimo 插件的 `write_custom` 必须先铺满 128 槽，再写 87 个逻辑颜色。

---

## 点亮的键不对（错位）

**原因**：用了 F87 **Pro** 的列优先矩阵。

| 键盘 | W 键槽位 |
|---|---|
| F87 Pro（网上多数开源项目） | 14 |
| **F87S（本项目）** | **34** |

F87S 是**行优先**且地址稀疏（Delete=106、PageDown=108），两套表互不兼容。
唯一权威来源是 [`data/f87s-calibration.json`](../data/f87s-calibration.json)，
不要从任何 F87 Pro 项目里抄矩阵。

---

## 找不到设备 / 枚举失败

```js
HID.devices()  // 先看看实际列出了什么
```

| 现象 | 处理 |
|---|---|
| 列表里没有 `0x38A6:0x2908` | 确认是有线连接；换 USB 口；换线 |
| 用无线 | 接收器是 `0x0C45:0xFEF9`，**和本体 PID 不同**，这是正常的 |
| 找到了但 `open` 失败 | Windows：被别的程序占用（退出 AULA Hub / SKYdimo）；Linux：缺 udev 权限，见 [`HID-PROTOCOL.md` §14](HID-PROTOCOL.md#14-跨平台注意事项) |
| 硬编码了 `\\?\HID#...` | 设备路径随 USB 口变化，**不要硬编码**，按 VID/PID + interface 枚举 |

---

## 无线：发了命令没回包

2.4G 接收器会**休眠**，首次查询经常超时。

1. 先按一下键盘上的实体键唤醒；
2. 查询失败最多重试 3–4 次（总尝试 ≤ 4），**不要无限重试**；
3. 还不行就重插接收器；
4. 每包等待建议 900 ms 起（这是主机策略，不是硬件要求）。

> 写入前用 `cmd16` 校验本体是 `38A6:2908`，防止同型号接收器配了别的键盘。

---

## 切换灯效预设后装饰灯区全黑

**原因**：`cmd43` / `cmd45` 的 24 字节参数块是**凭空构造**的，破坏了灯区预设参数。

正确做法：**先 `cmd27` / `cmd29` 读回原值当底稿，只替换 RGB 三字节**，其余原样回写。

```lua
string.char(original:byte(1), r, g, b) .. original:sub(5)
```

详见 [`HID-PROTOCOL.md` §5.5](HID-PROTOCOL.md#55-cmd27--cmd29--cmd43--cmd45--灯区参数24-b)。

## SKYdimo 相关

| 现象 | 处理 |
|---|---|
| 插件没生效 / 还是旧行为 | SKYdimo **优先加载用户目录** `%APPDATA%\Roaming\com.skydimo.desktop\plugins\`，它会**覆盖** `C:/Program Files/Skydimo/plugins/` 下的同名插件。先查用户目录里有没有旧副本 |
| 复制插件报 `EPERM` | `C:/Program Files` 需要**管理员权限** |
| 显示成三个输出 | 旧版本把按键/星环/侧灯注册成了三个输出。当前版本已合并为单个 `keys` |
| 设备被识别但灯不亮 | 「识别成功」≠「灯效通过」，中间还差一次目视确认。按上表前三条排查 |
| 灯效横竖颠倒 | 只交换 MAP 的 width/height 和坐标，**绝对不要改 `HARDWARE_IDS`**（那是实测校准值） |

---

## 键盘卡死 / 按键无响应

1. **拔插 USB**——一定能恢复；
2. 如果还会复发，检查是不是在高频发送 `cmd36` 且没有等 ACK；
3. **永远不要发 `cmd 79`（SET_FLASH_DOWNLOAD）**及任何校准 / 恢复出厂命令。

---

## 帧率上不去

| 现象 | 处理 |
|---|---|
| 每帧都要等约 54 ms | 那是 `lastFlag=1` 的设备端 stall。**连续帧改用 `last=0` 差分更新**，`cmd35` 只在初始化发一次（[§3.1](HID-PROTOCOL.md#31-lastflag-的重要实测性能优化关键)） |
| 差分没生效 | 确认 87 键地址落在前 8 个 56 B 分包内（是的），后 2 包无需逐帧重发 |
| 想跑 0x08 实时通道 | **别**。它在本机上未证实能显示，已禁用（[§9](HID-PROTOCOL.md#9--未走通的路径0x08-实时通道保持禁用)） |

---

## 还是不行

先跑一遍只读自检，确认组包逻辑没问题（不碰硬件）：

```bash
node tools/f87s-wireless-control.mjs selftest
```

再看看 [`CALIBRATION.md`](CALIBRATION.md) 第 7 节的验证步骤，逐键确认映射是否正确。
